# TASK-001 — UI-дизайн: Training Sessions Workspace

Роль: ui-designer. Статус: все развилки подтверждены пользователем лично (1=A..7=A). Код, зависимости, конфиги, requirements.md, architecture.md, api-integration.md и specs/ этим документом не изменяются. `specs/ui-design.md` не обновляется: направление относится к задаче и не подтверждено как общее.

Входы: requirements.md (v2), architecture.md (D-1..D-9, раздел 10), api-integration.md (разделы 5, 9, 12), DESIGN_TOKENS.md, sessions-dashboard-reference.svg (ориентир, не макет), фикстуры, ruleset `common/ui-designer` (product-context, web-interface-guidelines). Rulesets framework/project для ui-designer отсутствуют.

Пометка «НЕ ИЗМЕРЕНО» означает: значение рассчитано приблизительно и не проверялось инструментом; подтверждает browser-verify.

## 1. Принципы и границы

- Оператор тренерского бизнеса, частые повторные действия: приоритет у сканирования, сравнения и предсказуемых действий. Без hero, градиентов, вложенных карточек.
- Токены из DESIGN_TOKENS.md без изменений. Радиус не более 6px. Контрол от 40px, на мобильном цель от 44px.
- Отличия от reference (reference — только ориентир иерархии и плотности): нет бокового меню (другие разделы вне объёма), нет фильтра по типу (optional), детали в модалке вместо правой панели (D-1).
- Не меняются решения architect и api-integration: маршруты `/sessions` и `/sessions/:id`, нативный `<dialog>`, фильтры в URL, хуки и контракт.
- Язык интерфейса: английский (решение 4=A). Причина: данные фикстур и серверные `message`/`fieldErrors` английские, спека и контракт английские, i18n вне объёма; смесь языков на одном экране хуже. Тексты UI хранятся в одном месте на усмотрение плана (не требование).

## 2. Поток

1. Вход на `/sessions` (или `/sessions/:id`, deep link): рабочее пространство, поверх него (при `:id`) модалка деталей.
2. Оператор ищет и фильтрует (URL обновляется), при необходимости сбрасывает фильтры.
3. Клик по строке открывает детали по `/sessions/:id` с сохранённым query string. Закрытие возвращает на прежний URL списка.
4. «Create session» открывает вторую модалку (форма) без собственного URL. После успеха экран успеха внутри неё предлагает «Open session», «Create another», «Close».
5. Ошибки восстанавливаются на месте (повтор в области ошибки), приложение и фильтры остаются доступными.

Открытие формы поверх деталей не предусмотрено: детали — модальны, фон инертен. Форма и детали одновременно не открыты.

Известное ограничение (развилка 1=A): у формы нет URL, кнопка «Назад» браузера её не закрывает (уводит со страницы), перезагрузка теряет ввод. Принято пользователем.

## 3. Структура рабочего пространства

Порядок сверху вниз, всё в `<main>`:

1. Шапка: `h1` «Training sessions», справа primary-кнопка «Create session». Подзаголовок 14/20 muted («Find sessions, review capacity, and add new ones.») необязателен.
2. Панель инструментов (поверхность `surface`, рамка `border`): поле поиска, выбор статуса, «Clear filters».
3. Область списка: строка-счётчик («5 sessions», 14/700) и сам список либо состояние (loading, empty, no-match, error).
4. Постоянный live-регион статуса списка (см. раздел 10).

Панель инструментов:
- Поиск: `type="search"`, `<label>` «Search sessions» (визуально скрыта, видна программно), placeholder «Title, coach, or location…» цветом `text-muted`, `autocomplete="off"`, `spellcheck` выключен. Значение отражает локальный ввод, в URL пишется с debounce через `replace` (D-2).
- Статус: нативный `<select>`, метка «Status» (скрыта визуально), пункты: All statuses / Scheduled / Full / Cancelled / Completed.
- «Clear filters»: текстовая кнопка (secondary), видна только при активных фильтрах (непустой после trim `query` или заданный `status`). Перед скрытием фокус переносится на поле поиска.

Счётчик «N sessions» берётся из `meta.total` отфильтрованного ответа; при 1: «1 session».

Размеры и отступы: padding страницы 24px (десктоп), 16px (мобильный); промежутки 8/12/16/24px.

## 4. Список

### 4.1. Общая разметка и поведение

- `<ul>` с `<li>` на CSS grid (решение 3=A). Колонки на десктопе визуальные, строка заголовков колонок `aria-hidden` (SESSION, START, COACH, CAPACITY, STATUS; 11/700 muted).
- Скрытые подписи для скринридера в каждой строке (не обязаны быть видимыми): «Starts», «Duration», «Coach», «Location», «Capacity: 14 of 18», «Status: Scheduled», чтобы строка читалась осмысленно, а не потоком слов.
- Название — настоящая ссылка `<a href="/sessions/{id}{search}">`. Область клика растянута на всю строку (псевдоэлемент). Клик без модификаторов идёт через `navigate` слоя D-3 с флагом «из списка»; Cmd/Ctrl+click и средняя кнопка открывают в новой вкладке.
- Hover: фон `surface-muted`; hover не единственный способ узнать о действии, ссылка-название подчёркивается при фокусе.
- Длинное содержимое: название переносится (до 80 символов), `overflow-wrap: anywhere`; flex/grid-потомки с `min-width: 0`; адреса и локации переносятся.
- Числа и время с `font-variant-numeric: tabular-nums`.
- Даты и время только через `shared/lib/datetime` (Intl).

## 5. Модалка деталей

### 5.1. Общее

Нативный `<dialog>` с `showModal()` (D-1), `aria-labelledby` на `h2`. Монтируется при совпадении маршрута `/sessions/:id`. Закрытие идёт через навигацию (кнопка «×», кнопка «Close», Esc через перехват `cancel`, Назад).

- Десктоп: центрированный диалог шириной около 560px, максимальная высота `100dvh − 64px`. Структура: шапка (фиксированная), тело (прокручивается внутри), подвал (фиксированный).
- Мобильный (ширина менее около 640px, решение 2=A): полный экран (`100dvh`, без скругления), шапка с «×», тело прокручивается, подвал закреплён. Учитывается `env(safe-area-inset-*)`.
- Прокрутка только внутри тела диалога, `overscroll-behavior: contain`; фон не прокручивается (`body:has(dialog[open]) { overflow: hidden }` либо эквивалент). Горизонтальной прокрутки нет.
- Backdrop-затемнение на десктопе; клик по backdrop деталей закрывает диалог (через ту же навигацию), потери данных нет.
- Анимация появления: см. раздел 11.

### 5.2. Состав (AC-2.1)

Шапка:
- метка «SESSION DETAILS» (12/700, muted), `h2` с названием (19–20/700; в состояниях loading и error текст «Session details»), бейдж статуса (раздел 4.4), кнопка «×» с `aria-label="Close session details"` (иконка-кнопка 44×44 на мобильном, не менее 40×40 на десктопе).

Тело, по порядку:
1. Блок отмены (только если `cancellation` не `null`): «Cancelled» (красный акцент и иконка-крест плюс текст), «Reason: The gym is unavailable.», «Cancelled on Jul 27, 11:00» (дата через datetime-модуль). Это отображение уже существующей отмены `ses_104`; действия отмены нет (вне объёма).
2. Schedule: «Monday, Aug 3 at 18:00 (GMT+3)», «90 minutes». Короткое имя часового пояса показывается только в деталях.
3. Coach: имя; email как ссылка `mailto:`.
4. Location: название и адрес.
5. Capacity (Q-4, раздел 12.1).
6. Type и Visibility: «Training · Public» / «Private · Invite only».
7. Description.
8. Trainer notes.
9. Служебная строка 12/muted: «Created Jul 18, 12:30 · Last updated Jul 26, 09:15».

Данные деталей всегда берутся из `GET /api/sessions/:id`, а не из строки списка (D-4).

Подвал: кнопка «Close» (secondary, 40px / 44px на мобильном). Кнопки «Cancel session» нет.

### 5.3. null-значения (AC-2.2)

Description и trainer notes со значением `null` (или пустой строкой): секция остаётся с заголовком и приглушённым пояснением «No description provided.» / «No trainer notes.». Слово «null» не выводится, пустых заголовков-сирот нет. Решение обратимо (альтернатива — скрывать секцию) и записано как мелкое. Текст description и notes выводится с сохранением переносов строк (`white-space: pre-wrap`) и `overflow-wrap: anywhere`.

### 5.4. Состояния деталей

- loading: заголовок «Session details», скелетон блоков, `role="status"` с текстом «Loading session details…» (виден или скрыт визуально). Данные другого `id` не показываются (при смене `id` старые удаляются).
- error (кроме 404): внутри диалога блок `role="alert"`: «Session details couldn't be loaded», «Try again, or close this window and pick another session.», кнопки «Try again» (primary) и «Close».
- 404 `SESSION_NOT_FOUND`: «Session not found», «It may have been removed, or the link may be wrong.», кнопка «Back to sessions» (закрывает диалог; при прямом заходе ведёт на `/sessions` с сохранённым query). Кнопки «Try again» нет (повтор бессмыслен).
- idle (нет `id`): диалог не отображается.

## 6. Форма создания

### 6.1. Место и поведение (решение 1=A)

Второй нативный `<dialog>` с `showModal()`, без собственного URL. Состояние открытости локальное в `app` (колбэк для списка и кнопки «Create session»). `aria-labelledby` на `h2` «Create session». Размеры: десктоп около 640px, макс. высота `100dvh − 64px`, шапка и подвал фиксированы, тело прокручивается; мобильный (менее около 640px) полный экран. Горизонтальной прокрутки нет.

Backdrop клик форму не закрывает (решение 6=A). Esc, «×» и «Cancel» ведут к процедуре закрытия (6.6).

Обязательные звёздочкой не помечаются. `maxlength` не используется: ввод не обрезается молча, ошибка длины видна и связана с полем.

Спека и контракт верхнего предела не задают; предел выбран UI-дизайном как защита от огромных значений и поломки вёрстки (решение 7=A, подтверждено пользователем). Серверный предел неизвестен (api-integration, В-7). requirements-analyst может позже внести это ограничение в требования как отдельный AC; до тех пор оно не имеет статуса требования. Отдельный автотест границы не обязателен (AC-9.2).

Значения Type=Training и Visibility=Public выбраны как самые частые в фикстурах (3 из 5 и 4 из 5). Duration, Capacity, Date, Start time без значений по умолчанию: общего разумного значения нет, любое молча попало бы в данные.

### 6.3. Валидация и тексты ошибок

Чистая функция по trim-значениям (D-7), без библиотеки. Момент показа:
- у поля после `blur` (touched);
- у всех полей при попытке отправки;
- после первой попытки отправки поле перепроверяется при каждом изменении;
- серверная ошибка поля снимается при редактировании этого поля.

Тексты (формат «что исправить»):

| Поле | Ошибка |
|---|---|
| Title | «Enter a title of 3–80 characters.» |
| Date | «Choose a date.» |
| Start time | «Choose a start time.» |
| Дата и время вместе (в прошлом) | «Choose a date and start time in the future.» (привязана к паре Date и Start time) |
| Duration | «Enter a whole number of minutes from 30 to 240.» |
| Capacity | «Enter a whole number of places from 1 to 100.» |
| Coach | «Select a coach.» |
| Location name | «Enter a location name of 2–80 characters.» |
| Location address | «Enter an address of 3–120 characters.» |
| Description | «Description can be up to 1000 characters.» |
| Trainer notes | «Trainer notes can be up to 500 characters.» |
| Несуществующее локальное время (переход на летнее время) / невалидная дата | «This date or time doesn't exist. Choose another.» |

Связь ошибок с полями (AC-3.9, AC-7.5): у каждого поля `aria-invalid="true"` при ошибке и `aria-describedby` на подсказку и текст ошибки (id вида `{field}-hint`, `{field}-error`). Ошибка размещена сразу под полем, цвет `danger` плюс иконка-«!» и текст (не только цвет). Ошибка пары Date/Start time: `aria-describedby` на оба контрола; рамка красная у обоих.

При попытке отправки с ошибками: `POST` не отправляется, фокус на первое невалидное поле (в порядке DOM), polite-статус «N fields need attention» (в форме, `role="status"`).

Серверные ошибки:
- `400 VALIDATION_FAILED` с `fieldErrors`: строки показываются у соответствующих полей как есть (английские, серверные); ключи без соответствующего поля идут в блок формы. Введённые значения сохраняются. Фокус на первое поле с ошибкой.
- Блок формы (500 `CREATE_SESSION_FAILED`, сеть, malformed, `fieldErrors` без ключей полей): над кнопками подвала, `role="alert"`, `tabindex="-1"`; фокус переносится на него при появлении. Введённые значения сохраняются.

Тексты блока формы:
- 400: «Some fields need attention. Check the highlighted fields and submit again.»
- 500: «The session couldn't be created. Your entries are kept. Try again.»
- сеть или malformed (исход неизвестен): «We couldn't confirm that the session was created. Check the sessions list before submitting again, because a second submission may create a duplicate.» Кнопка «Create session» остаётся доступной (повторная отправка допустима).
- 409 `COACH_SCHEDULE_CONFLICT` и неизвестный код: используется текст 500; серверный `message` может быть показан второй строкой мелким шрифтом (на усмотрение реализации).

### 6.4. Coach и `coaches-error` (Q-6 UI-часть, решение 5=A)

Блокируется только поле Coach; остальная форма доступна. Тренеры запрашиваются при открытии формы (D-4).
- loading: select disabled, пункт «Loading coaches…».
- success: пункты по именам; выбор обязателен.
- error: на месте select встроенное сообщение `role="alert"`: «Coaches couldn't be loaded.» и кнопка «Try loading coaches again». После успешного повтора фокус на select Coach; после повторной ошибки фокус остаётся на кнопке повтора.
- Пустой `data`: «No coaches are available. Try loading coaches again.» с той же кнопкой. Валидного `coachId` нет.
- Кнопка отправки остаётся активной. Нажатие без валидного выбора не вызывает `createSession`: показывается ошибка у Coach («Select a coach.» либо сообщение об ошибке загрузки), фокус переносится на кнопку «Try loading coaches again» (при ошибке загрузки) либо на select.
- Если после повтора ранее выбранный тренер отсутствует в списке, выбор сбрасывается, поле получает «Select a coach.», фокус остаётся на повторе/селекте.
- Гарантия «не отправлять без валидного `coachId`» живёт в `useCreateSession` (api-integration, раздел 9); блокировка в UI дополняет её.

### 6.5. Pending и защита от дублей (AC-3.10)

- Кнопка «Create session» меняется на «Creating session…» (размеры не меняются), `aria-disabled="true"`; остаётся в фокусе, повторный клик игнорируется (флаг pending в `useCreateSession`).
- Поля становятся `readOnly` (select и radio блокируются так, чтобы фокус не терялся); «Cancel» и «×» неактивны; Esc игнорируется. Закрытие на время запроса запрещено (`POST` не отменяется, решение api-integration 10=A).
- Форма получает `aria-busy="true"`.

### 6.6. Закрытие с несохранёнными данными (решение 6=A)

- Форма «грязная», если хотя бы одно поле отличается от начальных значений.
- Esc, «×» и «Cancel» при грязной форме не закрывают диалог, а заменяют подвал на строку «Discard this session? Your entries will be lost.» с кнопками «Keep editing» (фокус на неё) и «Discard». Backdrop клик форму не закрывает вообще.
- Чистая форма закрывается сразу.
- Экран успеха (раздел 7) и состояние pending подтверждения не требуют.
- Если пользователь закрывает форму после неоднозначной ошибки `POST` (сеть или malformed), при закрытии выполняется явный `refetch` списка (D-4), чтобы увидеть, создана ли сессия. Контракт и архитектура не меняются.
- После закрытия фокус возвращается на кнопку «Create session».

## 7. Экран успеха (Q-5, решение 1=A)

После `201` форма внутри диалога заменяется экраном успеха:
- Заголовок `h2` «Session created» (диалог перелабеливается через `aria-labelledby`), `role="status"`; фокус на заголовок (`tabindex="-1"`).
- Сводка: «“{title}” is scheduled for {Mon, Aug 3 at 18:00}.» (время через datetime-модуль).
- Кнопки: «Open session» (primary), «Create another», «Close».
- При активных фильтрах (непустой `query` или заданный `status`): строка «Filters are active, so the new session may not appear in the list.» и кнопка «Clear filters».
- «Open session»: закрывает диалог и открывает `/sessions/{id}` с текущим query string (детали поверх списка), работает независимо от фильтров. «Clear filters» очищает `query` и `status` в URL (сохраняя посторонние параметры), диалог остаётся открытым, фокус остаётся на кнопке, которую заменяет подтверждающее сообщение «Filters cleared.» (polite-статус); кнопка «Clear filters» скрывается, фокус переносится на «Open session».
- «Create another»: возвращает пустую форму с начальными значениями (Type=Training, Visibility=Public), фокус как при открытии формы.
- «Close»: закрывает диалог, фокус на кнопку «Create session».
- Список перезапрашивается после успеха (D-4); созданная сессия в список вручную не вставляется.
- Автосброс фильтров не делается (меняет URL без согласия пользователя и ломает контекст).

Закрытие диалога Esc или «×» на экране успеха выполняется без подтверждения.

## 9. Живые регионы и семантика

- Постоянный регион статуса списка: `role="status"` (`aria-live="polite"`, `aria-atomic="true"`), размещён вне перерисовываемого списка (всегда в DOM). Озвучивает:
  - «Loading sessions…»;
  - после загрузки: «5 sessions» или «2 sessions match your filters»;
  - «No sessions yet» / «No sessions match your filters»;
  - после сброса: «Filters cleared. 5 sessions.».
  Результат озвучивается после завершения загрузки, а не на каждый символ поиска (debounce).
- Ошибка списка: блок `role="alert"` в области списка.
- Загрузка деталей: `role="status"` внутри диалога. Ошибка деталей: `role="alert"` внутри диалога.
- Ошибка уровня формы: `role="alert"` (фокус переносится на блок; повторная озвучка при фокусе допустима).
- Ошибки полей не являются live-регионами: связь через `aria-invalid` и `aria-describedby`; дополнительно polite-статус формы «N fields need attention» при отправке.
- Экран успеха: `role="status"`; подтверждение «Filters cleared.» в нём polite.
- Ошибка тренеров: `role="alert"` на месте поля.
- Приём на список при смене фильтров: прежние данные остаются на экране, приглушены (`opacity`), на списке `aria-busy="true"`; высота не скачет. Первичная загрузка показывает скелетон из 5 строк.
- Заголовки: `h1` «Training sessions» на странице, `h2` в каждом диалоге, `h3` для секций деталей и экрана формы при необходимости.
- Landmarks: `<main>`. Skip link не добавляется: до списка перед основным контентом только шапка и панель инструментов из трёх контролов (сознательное отступление от рекомендации guidelines).
- Иконки-кнопки (`×`) имеют `aria-label`; декоративные иконки `aria-hidden="true"`.

## 11. Reduced motion, touch и размеры

- Анимации опциональны и короткие: появление диалога fade и сдвиг на 8px не более 150ms, только `opacity` и `transform`, без `transition: all`. При `prefers-reduced-motion: reduce` анимации отключены, скелетон статичен, индикатор pending без вращения (текст «…»).
- Touch: `touch-action: manipulation`, цели на мобильном не менее 44px (контролы, «×», кнопки диалогов, строки списка), осознанный `-webkit-tap-highlight-color`.
- Фон диалога инертен, прокрутка внутри диалога (`overscroll-behavior: contain`).
- Pending-контролы сохраняют размеры (токены).
- Нет `user-scalable=no`. Поля формы не меньше 16px шрифта на мобильном, чтобы не приближать экран при фокусе (проверяет browser-verify).
- Hover не единственный способ узнать о действии; hover усиливает контраст, но не раскрывает скрытые действия.

## 12. Закрытые вопросы

### 12.1. Q-4: сводка по вместимости

В деталях блок Capacity:
- строка «14 booked of 18 places» и вторая строка «4 places left»;
- горизонтальная полоса 8px (как в reference), `aria-hidden`, смысл несёт текст; цвет `primary`;

- склонение: «1 place», «0 booked of 1 place»;

### 12.2. Q-5: действие после создания при скрытии фильтрами

Закрыт (1=A): экран успеха с «Open session» (всегда) и, при активных фильтрах, подсказкой и «Clear filters». Автосброса нет. Раздел 7.

### 12.5. Вопросы раздела 12 api-integration

- Q-6 UI-часть: см. 12.3.
- Тексты ошибок: список и детали (включая отдельный 404), тренеры, `VALIDATION_FAILED`, `CREATE_SESSION_FAILED`, `NetworkError`, `ResponseShapeError` определены в разделе 10; `fieldErrors` без поля уходят в блок формы.
- Сеть и malformed при POST: текст не утверждает «не создана», предлагает проверить список и допускает повтор с предупреждением о дубле; при закрытии формы после такой ошибки выполняется `refetch` списка (6.6).
- Смена входа хуков: при смене фильтров прежние данные списка остаются приглушённо (`aria-busy`) на время `loading`; при смене `id` деталей старые не показываются (скелетон нового); без `id` диалог не открыт.
- Пустой успешный список: «нет сессий» и «нет совпадений» различаются по наличию фильтров (непустой после trim `query` или заданный валидный `status`), не по API.

## 15. Что остаётся на реализацию

- Размер debounce (около 300ms), политика `replace` для статуса (D-2), пороговые ширины (около 640px для диалогов, около 720px для строк), конкретные иконки статусов.
