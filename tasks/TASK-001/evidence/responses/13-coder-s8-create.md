### Непроверенное из раздела 7 плана: что показал запуск
- **showModal:** `jsdom 31` не реализует `HTMLDialogElement.showModal/close` (уже записано в `setup.ts`). Минимального полифила хватает для второго диалога: `role="dialog"` находится по имени, а `aria-labelledby` меняется между формой и экраном успеха. Полифил не моделирует модальность, фокус-ловушку, инертность фона и Esc.
- **Фейковые таймеры:** подмена только `Date` (`toFake: ["Date"]`) с реальными таймерами работает с `userEvent`, MSW (в том числе с задержкой 150 мс через `setMockLatency`) и `waitFor`. Тесты зелёные.
- **Проверка «в будущем» при замороженном Date:** опираться на два факта.
  - `validate` берёт «сейчас» из `currentTime()`, то есть из замороженного `Date.now()`.
  - Тестовые даты отстоят от `FROZEN_NOW` на месяцы (2026-07-01 и 2026-09-15), поэтому пояс среды не влияет. Граница «ровно сейчас» не тестировалась, это тема R-теста `datetime`.
- **`user.type` в `type=date` и `type=time`:** в user-event 14 с jsdom работает, `fireEvent` не понадобился.

### Отклонения и решения по месту (прошу подтвердить)
1. **Блок формы при 400:** при 400 с известными ключами показываю блок `role=alert` с текстом 400 («Some fields need attention…») плюс ошибки у полей, фокус идёт на поле. ui-design 6.3 и раздел 10 допускают оба прочтения; выбрал вариант, где блок показывается.
2. **«Keep editing»:** фокус возвращается туда, где он был до подтверждения; если элемент исчез (Cancel в подвале), то на Cancel. В документах это не указано.
3. **Экран успеха:** заголовок «Session created» находится в теле, шапка при этом содержит только ×. Статус озвучивает заголовок, сводку и «Filters cleared.».
4. **Невалидный выбор тренера:** «Select a coach.» показывается также при загрузке или ошибке списка, то есть валидный `coachId` определяется последним успешным списком (`coachIds` в `validate`). Guard в хуке остаётся второй линией защиты.
5. **Правила валидации:** числа проверяются строго по `^\d+$` (запись «1e2» отклоняется). Длина считается по trim-значению, счётчики по сырой длине.
6. **Не реализовано:** второй строкой серверный `message` для 409/неизвестного кода не показывается (на усмотрение ui-design). Адаптив, анимации и `prefers-reduced-motion` для диалога формы не делал (S9).

### Риски
- Повторное открытие `showModal` в обработчике `close` и StrictMode (в dev `main.tsx` использует StrictMode) подтверждает только browser-verify.
- `now` берётся при рендере (`currentTime()`): ошибка «в будущем» обновляется при следующем рендере, а не по таймеру.
- Правка дубля классов `details-*` для формы оставлена на S9.
- Открытие формы поверх деталей блокируется в `App`, а не только инертностью фона. Реальная инертность не проверена.
