**Фокус**
- Детали из списка: `showModal()` по умолчанию фокусирует первый фокусируемый элемент. Задаём явно: фокус на `h2` (`tabindex="-1"`). Скринридер читает название диалога и заголовок, прокрутка тела не смещается.
- Прямой заход на `/sessions/:id`: то же самое. Список загружается под диалогом, фокус не прыгает.
- Закрытие любым способом (кнопка, Esc, Назад): фокус возвращается на ссылку строки этой сессии (по id), если она есть в списке. Нативный возврат фокуса при навигационном закрытии ненадёжен (opener мог перемонтироваться, при deep link opener отсутствует), поэтому возврат делаем явно. Если строки нет (deep link, фильтры скрыли), фокус идёт на `h1` (`tabindex="-1"`).
- Форма создания: на десктопе первичный фокус на первом поле (Title). Если указатель coarse (мобильный), фокус на заголовок формы, чтобы не поднимать клавиатуру (рекомендация guidelines про `autoFocus`).
- Фокус после ошибок формы и успеха описан ниже, раздел «Создание».
- После сброса фильтров фокус на поле поиска (кнопка сброса исчезает).
- Esc и кнопка закрытия идут через одну навигацию (D-1). Закрытие во время `pending` в форме запрещено (см. ниже).

**Живые регионы**
- Один постоянный `role="status"` (`aria-live="polite"`, `aria-atomic`) на уровне списка, вне перерисовываемого контента. Он озвучивает:
  - «Loading sessions…»;
  - «5 sessions» или «2 sessions match your filters» (после загрузки, без озвучки при каждом символе поиска);
  - «No sessions match your filters» / «No sessions yet»;
  - «Filters cleared. 5 sessions.»
- Ошибки списка: блок с `role="alert"` в области списка.
- Ошибки деталей: `role="alert"` внутри диалога.
- Состояние загрузки деталей: `role="status"` внутри диалога.
- Создание: подтверждение успеха `role="status"`, ошибка уровня формы `role="alert"`.
- Ошибки полей не live: связь через `aria-invalid="true"` и `aria-describedby` (подсказка плюс текст ошибки). Дополнительно polite-статус формы «3 fields need attention».
- Приём на список при смене фильтра: прежние данные остаются на экране с `aria-busy="true"` и приглушением, без скачков высоты. Первичная загрузка показывает скелетон из 5 строк. Для деталей другого `id` старые данные не показываем.

**Форма создания: структура (место и успех см. развилку 1)**
- Поля и подписи (видимые `<label>`, пометка «(optional)» у необязательных, обязательные отдельной звёздочкой не помечаем):
  - Title (`type="text"`, `autocomplete="off"`, подсказка «3–80 characters»);
  - Session type (select: Training / Camp / Private);
  - Date (`type="date"`) и Start time (`type="time"`) рядом, подсказка «Your local time (GMT+x). Must be in the future.»;
  - Duration (`type="number"`, `inputmode="numeric"`, суффикс «minutes», подсказка «Whole number, 30–240»);
  - Capacity (`type="number"`, суффикс «places», подсказка «Whole number, 1–100»);
  - Coach (select, первый пункт «Select a coach»);
  - Location name («2–80 characters»);
  - Location address («3–120 characters»);
  - Visibility (radiogroup в `fieldset/legend`: Public / Invite only);
  - Description (optional, textarea);
  - Trainer notes (optional, textarea, счётчик «0 / 500»).
- Атрибуты `maxlength` не ставим: ввод не должен молча обрезаться, ошибка длины должна быть видна и связана с полем. Счётчик показываем при приближении к лимиту.
- Валидация (AC-3.1..3.8) в чистой функции по trim-значениям.
- Момент показа ошибок: у поля после `blur` (touched) и у всех полей при попытке отправки. После первой попытки отправки поле перепроверяется на каждом изменении. Серверная ошибка поля снимается при редактировании этого поля.
- При попытке отправки с ошибками: `POST` не уходит, фокус на первое невалидное поле, polite-статус «N fields need attention».
- Ошибка «в будущем» привязана к паре Date/Time (`aria-describedby` на оба контрола). Ошибки «Choose a date» / «Choose a start time» отдельно.
- Серверный `400` с `fieldErrors`: ошибки показываются у полей по ключам, не совпавшие с полем ключи идут в блок формы. Введённое сохраняется. Фокус на первое поле с ошибкой.
- Ошибка уровня формы (500, сеть, malformed, `fieldErrors` без полей): блок `role="alert"` над кнопками, `tabindex="-1"`, фокус на него. Введённое сохраняется.
- Pending: кнопка «Creating session…» с неизменными размерами, `aria-disabled="true"` (остаётся в фокусе, повторный клик игнорируется, нет дублей `POST`), поля `readOnly`/заблокированы, Esc и «×» неактивны на время запроса. Результат ждём всегда.

**Reduced motion и касание**
- Появление диалога: fade и сдвиг на 8px не более 150ms только через `opacity`/`transform` (без `transition: all`). Под `prefers-reduced-motion: reduce` анимация убрана, скелетон статичен, спиннера нет (текст «…»).

- Hover не единственный способ узнать о действии. Строка списка получает hover-фон и всегда видимый фокус.

**Адаптивность модалок на 390×844**
- См. развилку 2 (полный экран против шторки). Прокрутка внутри диалога, горизонтальной прокрутки страницы нет, учтён `env(safe-area-inset-*)`.

## (в) Развилки, требующие решения пользователя

### 1. Форма создания: где живёт и как показан успех (включая Q-5)
Суть: форма и подтверждение успеха. Выбор влияет на маршрутизацию, поток и возврат фокуса.

- **Вариант A (рекомендую).** Форма во втором нативном `<dialog>` без собственного URL; состояние открытости локальное в `app`. Поверх деталей не открывается (фон инертен). После успеха диалог остаётся открытым и заменяет форму экраном успеха:
  - заголовок «Session created», `role="status"`, фокус на заголовок;
  - краткая сводка (название, время);
  - кнопки «Open session» (primary), «Create another», «Close»;
  - если фильтры активны, дополнительная строка «Filters are active, so the new session may not appear in the list.» и кнопка «Clear filters».
  - Плюсы: маршрутизация D-3 не меняется, фокус не теряется, подтверждение явное (AC-3.12), форма не размонтируется «из-под» пользователя. Минусы: у формы нет deep link, кнопка «Назад» не закрывает форму (уводит со страницы), перезагрузка теряет ввод. Подтверждение исчезает после закрытия.
- **Вариант B.** Маршрут `/sessions/new`. Плюсы: deep link, Назад закрывает. Минусы: меняет D-3/D-5 (пришлось бы менять architecture.md, это вопрос к архитектору), больше кода маршрутизации, расходится с запретом разрастания.
- **Вариант C.** Форма в модалке, после успеха диалог закрывается и сверху списка постоянный баннер-подтверждение с теми же действиями. Плюсы: подтверждение живёт на странице и не пропадает. Минусы: фокус нужно переносить на баннер, лишний постоянный элемент, баннер нужно сбрасывать.

Рекомендация: **A**. Нет изменений архитектуры, самый короткий поток для оператора, подтверждение и действия рядом. «Open session» открывает `/sessions/:id` с текущим query (детали поверх списка), что работает независимо от фильтров. Закрытие после «Open session» возвращает фокус по общему правилу (строка либо `h1`).

### 2. Модалки на мобильном: полный экран или нижняя шторка
- **A (рекомендую): полный экран** (`100dvh`, без скругления, шапка с «×» и заголовком, тело прокручивается, подвал закреплён). Плюсы: максимум места для формы с 11 полями и клавиатурой, нет жестов, проще a11y и тесты. Минусы: «теряется» контекст списка визуально (но он под диалогом).
- **B: шторка снизу** (около 85% высоты, ручка). Плюсы: сохраняется ощущение контекста. Минусы: нужны жесты или иначе видимая ручка без жестов, проблемы с экранной клавиатурой и safe-area, больше риска переполнения на 390×844.
- **C: полный экран для формы, шторка для деталей.** Минусы: два паттерна.

Рекомендация: **A** для обеих модалок на ширине меньше 640px (десктоп 560px для деталей и 640px для формы центрированно).

### 3. Разметка списка: `<ul>` с CSS grid или `<table>`
- **A (рекомендую): `<ul>/<li>` на grid.** Колонки визуальные, на мобильном строка перестраивается в стек. Плюсы: одна разметка без потери семантики при `display: block`, ссылка-название в строке, легко растянуть область клика. Минусы: нет табличных `th` (заголовки колонок визуальные, `aria-hidden`; смысл каждого поля передаёт текст строки: «Coach:», «Capacity: 14 of 18» через скрытые подписи).
- **B: `<table>` на десктопе, перестройка в блоки на мобильном.** Плюсы: нативная табличная семантика, сравнение колонок. Минусы: при переопределении `display` у `tr/td` семантика теряется в части браузеров, нужен ARIA или две разметки; сложнее растянуть клик; больше риск в тестах.
- **C: две разметки (таблица на десктопе, список на мобильном, переключение CSS).** Минусы: дублирование контента, дважды в DOM (`display:none`), риск двойных находок в тестах.
