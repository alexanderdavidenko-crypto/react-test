## 1. Реализованный объём

Frontend-приложение без бэкенда: API мокается через MSW (`msw@2.14.6`) по контракту из `frontend-accelerator-assessment/API_CONTRACT.md`.

- Список сессий: поиск и фильтр по статусу, синхронизированные с URL (`?query=`, `?status=`; запись через `replace`, debounce 300 мс; кнопки Назад и Вперёд сохраняют соответствие списка URL). Состояния: загрузка, пусто, нет совпадений (отдельное сообщение), ошибка списка с «Try again». Колонки на 1440, стек строк на 390.
- Детали сессии: нативный `<dialog>` на маршруте `/sessions/:id` поверх списка, прямой заход и deep link. Состояния: загрузка, успех, ошибка с «Try again», 404 («Back to sessions»). Значения `null` не показываются как слово «null».
- Форма создания: второй `<dialog>` без URL. Клиентская валидация AC-3.x, защита от повторной отправки, ошибки полей и формы (в том числе 400 `fieldErrors`), `coaches-error`, экран успеха («Open session», «Create another», «Close», «Clear filters» при активных фильтрах), подтверждение закрытия «грязной» формы.
- Мок (только dev): шесть сценариев `normal`, `empty`, `list-error`, `details-error`, `coaches-error`, `create-error` через `?scenario=` и `VITE_MOCK_SCENARIO`; stateful создание сессии.
- Адаптив 1440×900 и 390×844 без горизонтальной прокрутки, цели касания 44 px и шрифт полей 16 px на мобильном, видимый фокус, `prefers-reduced-motion`.
- Тесты: 186 тестов в 12 файлах (раздел 4 и 5.1).
- README с командами запуска и сценариями мока.

Сценарии network и malformed в моке отсутствуют по дизайну (их нет в `mock-scenarios.json`); в браузере они воспроизводились подменой `window.fetch`, в автотестах покрыты в `client.risk.test.ts`.

Историю работы по коммитам см. в `tasks/TASK-001/workflow-log.md` (таблица ролей и хеши коммитов); ключевые: `6a0019e` (чекпоинт планирования до кода, хеш записан в шапке лога), `a53becc` (foundation), `651fcba`, `787d5fb`, `3d98cd5` (срезы S6–S9), `fd58ebf` (правки по browser-verify).
